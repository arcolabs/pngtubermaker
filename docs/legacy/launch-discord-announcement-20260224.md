# PNGTuberMaker — Discord 上线通知方案

> Created: 2026-02-24

---

## 0. 目标

在已有的 Discord 社区中完成产品正式上线通知，达成：
1. 首批 20-50 个真实用户注册并试用
2. 收集 5-10 条用户反馈和作品截图（作为 Product Hunt 的社交证明素材）
3. 建立早期社区氛围，让用户愿意留下来

---

## 1. 发布前准备（D-2 ~ D-1）

### 1.1 准备展示素材

在发公告之前，先准备好以下内容：

| 素材 | 用途 | 要求 |
|------|------|------|
| 6-8 张不同风格的头像成品图 | 公告配图 + #showcase 频道铺底 | Anime、Chibi、Pixel 等风格各一 |
| 1 段 60 秒屏幕录制 | 展示 prompt → 生成 → OBS 使用全流程 | 不需要精致，真实感更重要 |
| 1 张产品首页截图 | 嵌入公告消息 | 清晰展示核心功能 |

### 1.2 设置 Discord 频道

确保社区内有以下频道结构：

```
#announcements     — 正式公告（仅管理员发言）
#showcase          — 用户晒作品（鼓励互动）
#feedback          — 反馈和建议
#bugs              — Bug 反馈
#general           — 自由讨论
```

### 1.3 准备限时福利

冷启动阶段的核心杠杆是降低试用门槛：

- **方案 A（推荐）**：Discord 成员专属，注册即送 **1,000 credits**（比默认 500 翻倍），有效期 14 天
- **方案 B**：前 50 名注册用户送额外 500 bonus credits
- **方案 C**：不做额外福利，直接用默认 500 free credits

> 推荐方案 A。1,000 credits 足够生成 1 个完整角色 + 3-4 个表情，成本约 $0.15/人，50 人 = $7.5，几乎没有成本压力，但大幅提高首次体验完整度。

## 2. 正式公告文案

### 2.1 主公告（#announcements）

```markdown
🎉 **PNGTuberMaker 正式上线了！**

经过几周的开发和测试，PNGTuberMaker 终于可以正式使用了。

**它是什么？**
一个 AI 工具，帮你用文字描述生成 PNGTuber 头像 — 从输入 prompt 到直播可用，2 分钟搞定。

**能做什么？**
→ 文字描述生成角色头像
→ 一键生成表情包（开心/生气/难过/惊讶）
→ 直接生成 OBS Browser Source 链接，粘贴即可直播
→ 不用安装任何软件，不用 veadotube

**多少钱？**
注册免费，送 500 credits，够你生成第一个完整角色试试效果。
🎁 **Discord 社区专属**：本周注册额外赠送 500 credits（共 1,000），够完整体验全部功能。

👉 **立即试用**：https://pngtubermaker.com

试完了来 #showcase 晒你的角色！有任何问题和建议发到 #feedback，我会逐条看。
```

### 2.2 配图建议

公告消息附带：
1. **一张拼图**：4-6 个不同风格的成品头像拼在一起（体现多样性）
2. **或一段 GIF/短视频**：prompt 输入 → 头像生成的过程（体现速度）

### 2.3 跟进消息（发布后 1-2 小时）

在 #general 频道发一条更轻松的消息：

```markdown
刚发了公告，PNGTuberMaker 上线了 🙌

说实话有点紧张，这是我一个人做的项目。如果你试用了，能告诉我：
1. 生成效果达到你预期了吗？
2. 有没有哪个地方卡住了或者不好用？
3. 你会考虑用它来直播吗？

任何反馈对我都超级有价值。直接发这里就行。
```

> 这条消息的目的是降低用户反馈的门槛。公告频道太正式，用户不敢说真话。在 general 用更个人化的语气，独立开发者的身份反而是优势。

## 3. 发布后运营动作

### 3.1 第一天（D-Day）

| 时间 | 动作 |
|------|------|
| 发布后 0-1h | 主动在 #general 和用户互动，回答问题 |
| 发布后 2-4h | 自己先在 #showcase 发 2-3 个头像作品"抛砖引玉" |
| 发布后 4-8h | 对每个在 #showcase 发作品的用户逐一回复、点赞 |
| 当天晚上 | 汇总当天的 bug 反馈，列出优先级 |

### 3.2 第一周（D+1 ~ D+7）

| 动作 | 目的 |
|------|------|
| 每天在 #showcase 发 1 个新风格的头像 | 保持频道活跃度 |
| 快速修复用户反馈的高优 bug | 展示"你的声音被听到了" |
| 私信 3-5 个活跃用户问更深入的反馈 | 收集深度用例和痛点 |
| 收集用户作品截图和评价 | 为 Product Hunt 准备素材 |
| 统计注册/生成/完成率数据 | 为 PH 文案提供数据支撑 |

### 3.3 关键数据追踪

| 指标 | 目标 | 衡量方式 |
|------|------|----------|
| 注册用户数 | 30+ | 数据库 user 表 |
| 完成首次生成 | 60%+ | generatedAvatars 表 |
| 完成表情包 | 30%+ | 单用户多个 expression 记录 |
| #showcase 发帖 | 5+ | Discord 频道统计 |
| Bug 反馈数 | 记录即可 | #bugs + #feedback |

---

## 4. 注意事项

1. **不要群发 @everyone**。用 @here 或角色标签（如 @Streamer），避免引发反感
2. **不要过度承诺**。说"正在开发中"而不是"即将上线"来描述未完成的功能
3. **坦诚面对 bug**。上线初期一定有问题，快速响应比完美产品更重要
4. **截图保存好评**。用户在 Discord 说"这个好酷"这种自然反馈，截图保存，PH 上线要用
5. **控制预期**。强调"这是第一个版本，你的反馈会直接影响后续方向"
